各設計數據與消融實驗

    模型知道自己哪裡沒把握

    不確定度＝Ensemble 三個成員（RF、Multimodal、ViT）意見的分歧程度，推論時就能算，不需要答案。

    各設計數據

    對照組「離閾值遠近」：分數越接近閾值越不確定。網頁上的「沒把握」門檻為測試設計所有區塊中不確定度前 20%。

    完整數據：測試設計 Vortex-small

    粗體為該欄最佳。「贏 eGR 的版圖」是逐張版圖比較 F1。

    限制

    • 只有 3 個設計，平均 ± 標準差只來自 3 個數字；每組實驗只訓練一次（seed 42）。
    • 同設計 vs 跨設計有落差：同設計驗證集 ROC-AUC 約 0.99，換成沒看過的設計是 0.89–0.99。
    • 設計之間分布差很多：熱點比例 10%–68%、macro 有無、原始尺寸差約一倍。
    • ROC-AUC 穩定、F1 隨設計變動：「多擠才算熱點」的閾值需要依設計調整。

    方法與流程

    只用 placement 後就能取得的資訊，預測 routing 後的壅塞。工程師不用等 routing 跑完（數小時以上）才發現哪裡塞爆。

    系統流程

    1. 輸入Placement 後的版圖4 張特徵圖：cell 密度、RUDY、腳位 RUDY、macro
    2. 第二種模態設計參數時脈、使用率、macro 擺法、電源網路、filler 時機
    3. 鑑別式模型區塊分類＋逐像素回歸8×8 區塊判斷熱點；U-Net 預測整張使用率圖
    4. 輸出熱點圖＋可信度＋依據不確定度標出沒把握的區塊；Grad-CAM 顯示判斷依據

    標註：routing 後的真實繞線使用率；區塊平均 ≥ 0.6 為熱點。依設計切分，避免「考到看過的題目」。

    比較的方法

    ROC-AUC：Vortex-small ／ 三個設計平均

    資料：CircuitNet-N14

    每個設計的 96 張版圖＝同一顆電路的 96 種設計參數組合，各跑一次完整的實體設計流程。

    系統架構

    資料串流解壓 CircuitNet，面積平均縮成 256×256
    模型PyTorch、torchvision（ViT-B/16、ResNet-18）、OpenCV、scikit-learn
    訓練Colab T4，三個設計輪流測試
    後端Flask REST API；啟動時預先算好範例
    前端HTML / CSS / JS，Canvas 繪圖，離線可用
